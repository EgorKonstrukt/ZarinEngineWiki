# Упаковка .zplugin

Подписанный дистрибутируемый формат: один файл с кодом, нативными модулями, bundled-библиотеками и манифестом — установка броском внутрь, верификация до первого выполнения.

Анатомия пакета:

- Манифест: имя, версия, описание входа, список `dependencies` (другие плагины/библиотеки с версиями), опциональные `cython_modules` для bundled нативных сборок.
- Кодовые записи: `.py`-модули через стандартную фабричную конвенцию.
- Нативные записи: `.pyd` / `.so` / `.dll` по дисциплине `_native/` — верификатор отвергает неиндексированные нативные модули сразу.
- `libs/` bundled-зависимости, активируемые на плагин, изолированно от версий других плагинов.

Инструменты сборки: `tools/build_plugin.py` собирает обычный каталог плагина; `tools/build_zplugin.py` компилирует нативные части (Cython через cythonize при настройке), пакует манифест, код, natives и libs в архив `.zplugin`.

Поток установки и верификации:

1. Бросьте файл куда смотрит менеджер (или установите из панели пакетов).
2. `verify_zplugin_file` (`core/foundation/plugins/discovery.py:80`) валидирует манифест, сообщает недостающие зависимости по именам, проверяет индекс записей; файлы payload перепроверяет `_verify_payload_files` (несовпадение хэша — `modified file`, неиндексированные `.pyd`/`.so`/`.dll` вне `_native/` отвергаются).
3. Подписи (`verify_manifest_signature`) проверяются по `config/trusted_keys` `*.pub` (64-hex ed25519-ключи, плюс опциональный `trusted_keys_dir`); политика `allow_unsigned` (дефолт `warn`, `strict` блокирует): без ключей верификация отвечает `no trusted keys configured`, а не молча пропускает.
4. `_zplugin_fingerprint` (`core/foundation/plugins/ui_registry.py:130`, sha256 + размер + mtime) спрашивает кэш распаковки — переустановки неизменных файлов бесплатны.
5. Активация резолвит зависимости, монтирует bundled libs, грузит вход.

Обновления: поднимите версию манифеста, пересоберите, раздайте — отпечаток меняется, кэш распаковывается заново, зависимые перерезолвятся. Держите `NAME` стабильным между версиями, иначе сиротеют конфиги.

В репозитории пример артефакта: `plugins/mcp_pack-2.1.1.zplugin` — вскройте как архив: настоящий манифест, нативная раскладка, схема версионирования.

Диагностика: отказ неподписанному — подпишите доверенным ключом или добавьте ключ; недостающая зависимость — сначала поставьте именованный пакет; несвежее поведение после пересборки — не изменился отпечаток (гранулярность mtime), троньте или bump версии; падение нативной загрузки — mismatch архитектуры (win `.pyd`/`.dll` против linux `.so`).

Связанное: менеджер плагинов (цепочка верификации), гид пользовательских (что паковать), каталог системных.
