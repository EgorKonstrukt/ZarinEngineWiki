# Сетевой плагин (страница плагина)

Системный плагин (`network_plugin.py`, `SYSTEM = True`, `DESCRIPTION` "Multiplayer transport using GameServer/GameClient over TCP") — мост геймплейного кода и синглтона транспорта.

Факты стороны плагина:

- Грузится в системном тире при старте редактора/движка; `initialize` логирует готовность, `shutdown` чисто отключается — сессии не переживают выход.
- Выставляет состояние сессии свойствами: `is_connected`, `is_server`, `local_id`, `peer_count` — все под guard исключений, безопасны для UI-кода.
- `host(port=7777, max_players=16)` биндит все интерфейсы; `connect(host, port)` входит как `"Player"`; оба логируют и возвращают bool.
- Сообщения едут фреймами `MessageType.NET_RPC`: `send(type, payload, target_id)` таргетит одного пира с сервера или broadcastит иначе; `broadcast(type, payload)` всегда веером.
- Подписки `on_message(type, handler)` кормят `NetworkMessage(msg_type, payload, sender_id)`; wildcard `"*"` ловит необработанное для логов. `_dispatch_rpc` изолирует исключения похендлерно.
- `poll()` осушает фреймы транспорта, раздаёт RPC, возвращает остаток назад в транспорт — не-RPC протоколы сосуществуют нетронутыми.
- `handle_transport_messages(msgs)` — шов для других систем: возвращает необработанные фреймы наверх.

Полные паттерны сообщений, формы payload и рецепты сессий — в разделе сети (транспорт и протокол, NetworkManager, страница использования); здесь плагин как гражданин движка: где грузится, чем владеет, как гасится.

Диагностика (скоуп плагина): хендлеры молчат — не качается `poll()` или подписка после старта трафика; двойная обработка — хендлер подписан дважды (подписки appendятся); сессия пережила выход — обойдён shutdown, в тулинге всегда disconnect явно.

Связанное: раздел сети (протокол, менеджер, компоненты), менеджер плагинов (системный тир), жизненный цикл PluginBase (используемые хуки).
