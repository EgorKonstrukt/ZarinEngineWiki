# MCP-мост

MCP-сервер (Model-Context-Protocol), выставляющий операции движка AI-агентам: запросы сцены, создание объектов, правки свойств, скриншоты, выполнение кода — та же поверхность, что ведёт этот документирующий процесс.

Раскладка в `plugins/zarin_mcp/`:

- `mcp_server.py` — сервер протокола: регистрация инструментов, диспатч запросов, фрейминг ответов.
- `registry.py` — каталог инструментов: каждая операция регистрируется с именем, схемой и хендлером.
- `handlers/` — модуль на домен (сцена, объекты, вьюпорт, выполнение), файл сервера остаётся худым.
- `main_thread.py` — диспатч GUI-потока: мутации документа и видов обязаны идти в главном потоке, фоновые запросы маршалятся сюда.
- `mcp_dock.py` — панель редактора: статус сервера, подключённые клиенты, лог запросов, старт/стоп.

Корни в репозитории: `zarin_mcp_config.json` и `zarin_mcp_launcher.py` в корне проекта конфигурируют и запускают мост вне редактора; `plugins/mcp_pack-2.1.1.zplugin` шипает его подписанным дистрибутивом (см. упаковку).

Процесс: запустите мост (док или лаунчер) → подключите MCP-агента конфигом → агент листает инструменты реестра → правки сцен идут валидированными операциями со скриншотами назад. Каждая мутация — явный tool call, аудируемый в логе дока.

Поза безопасности: мост может переписывать сцены и выполнять код — биндите на localhost, запуски за выключателем дока, лог запросов ревьюйте как sudo-историю.

Диагностика: агент не коннектится — сервер не стартовал или неверный путь конфига; инструмента нет — реестр домена не загружен, смотрите док; лаги правок — очередь главного потока насыщена, снизьте rate запросов.

Связанное: упаковка .zplugin (шиппабельный пак), менеджер плагинов (тир загрузки), гизмо (что видят агенты).
