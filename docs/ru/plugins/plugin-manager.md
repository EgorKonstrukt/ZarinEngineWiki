# Менеджер плагинов

Discovery, порядок, безопасность и разборка всего подключаемого. Один класс `PluginManager`, три тира плагинов: встроенные `.py`, нативные бинарники, подписанные пакеты `.zplugin`.

Discovery и порядок:

- Системные грузятся из `plugins/` первыми, пользовательские из `plugins/user/` после. Регистрация дописывает `_load_order`; разборка идёт в обратном порядке — зависимые освобождаются раньше зависимостей.
- `get_system_plugins()` фильтрует тир; итерационные хелперы отдают инстансы в порядке загрузки для кадров (`step`/`pre_step`) и веера событий (хуки сцен, play, окна).
- Замена плагина (тот же `NAME`, новый путь) меняет запись на месте вместо дублирования — горячая итерация без рестартов для чисто-Python плагинов в части потоков.

Нативные бинарники:

- Записи `.dll` / `.so` грузятся нативным путём с записью `_native_plugin_path` на инстанс; соседняя папка `<name>_resources` авторезолвится как `resource_dir`.
- Каталоги bundled-зависимостей активируются на плагин (`_activate_bundled_libs`) — два плагина везут конфликтующие версии библиотек, не травя друг друга.

Security-цепочка `.zplugin`, сверено по шагам:

1. `verify_zplugin_file` проверяет манифест (имя, версия, список `dependencies` с отчётами о недостающих), индексирует каждую запись, отвергает неиндексированные нативные модули (дисциплина `_native/` для `.pyd`/`.so`/`.dll`).
2. Подписи проверяются по доверенным ключам из `config/trusted_keys` (плюс опциональный настроенный каталог); без настроенных ключей верификация сообщает "no trusted keys configured", а не молча пропускает.
3. `_zplugin_fingerprint` (sha256 + размер + mtime) гейтит кэш распаковки: неизменные пакеты переиспользуют распакованное дерево, изменённые распаковываются заново.
4. Зависимости манифеста резолвятся (включая bundled Cython-сборки через `cython_modules`); недостающие явно логируются и блокируют активацию.

Конфигурация: перплагинные security-ручки (`check_updates_on_startup`, `trusted_keys_dir`) питаются из security-конфига; перплагинные данные persist через load/save базового класса.

Поза при падениях: сломанный плагин логируется и скипается — одно гнилое яблоко никогда не мешает старту редактора. Сначала консоль; панель менеджера плагинов зеркалит состояние, порядок и ошибки.

Связанное: жизненный цикл PluginBase, упаковка .zplugin, гид пользовательских, каталог системных.
