# MeshFilter

Отвечает *что* рисовать: ассет меша плюс имя субмеша внутри многосоставных файлов. Настроек внешности нет — они на рендерере.

| Поле | Смысл |
|---|---|
| mesh_path | Файл модели: `.obj`, `.fbx`, `.stl`, `.gltf`, `.glb`, `.usdz`, `.dae`, `.blend`, `.3ds` и другие через мост Assimp C-FFI |
| mesh_name | Селектор субмеша внутри файла |

Конвейер импорта: Assimp читает вершины, нормали, UV, тангенты, цвета и веса скиннинга в numpy-массивы (OBJ-парсер фолбэком для групп материалов, GIF-импортёр для анимаций кадрами), результат кэшируется в `Library`, кэш геометрии загружает в GPU один раз. Файловый `.import` JSON управляет масштабом, генерацией нормалей/тангентов и углом сглаживания.

Один ассет кормит сразу трёх потребителей: MeshRenderer (картинка), MeshCollider (физика) и миниатюру превью — один реимпорт обновляет всех.

Процесс: импорт модели, проверка в превью, `.import`-масштаб чтобы единица равнялась метру, назначение в MeshFilter, материалы по субмешам на рендерере. Многосоставной FBX: по сущности на `mesh_name` с общим путём.

Диагностика: нет субмеша — опечатка `mesh_name` или несвежий импорт, реимпорт и перепейк; неверный масштаб — `.import` против юнитов сцены; чёрные нормали — включить генерацию в `.import`; розовое — бит путь материала рендерера, не фильтра.

Связанное: MeshRenderer, SkinnedMeshRenderer, MeshCollider, импорт моделей, превью материалов.
