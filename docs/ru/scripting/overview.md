# Обзор скриптинга

Поведения сущностей в ZarinEngine — обычные `.py`-файлы с классом поведения. Базовый класс и регистрация не нужны.

Создание: `Project → Create → Python Script`, назначение на сущность: `Inspector → Add Component → Scripts`, запуск кнопкой `Play`.

```python
from core.maths.math3d import Vec3


class Mover:
    speed: float = 5.0

    def on_update(self, dt: float):
        t = self._entity.transform
        if t:
            t.translate(Vec3(0.0, 0.0, self.speed * dt))
```

Как это работает:

- Движок находит первый класс в файле, у которого есть хотя бы один колбэк жизненного цикла (или `_inspector_buttons`). Наследоваться ни от чего не нужно.
- Конструктор — обычный `__init__` без аргументов. Движок сам выставляет `self._entity` перед каждым вызовом.
- Короткие имена — полноценные алиасы: `update` = `on_update`, `start` = `on_start` и так далее. Если заданы оба варианта, вызывается `on_*`-версия.
- На одной сущности разрешено несколько `ScriptComponent` (`_allow_multiple = True`).
- Исключение внутри любого колбэка не роняет игру: ошибка пишется в консоль с именем скрипта и метода, кадр продолжается.

Подстраницы:

- Колбэки жизненного цикла — полная таблица методов и сигнатур.
- Поля инспектора и Range — как аннотации класса превращаются в виджеты.
- API ввода и математики — что подставляется в каждый скрипт автоматически.
- Горячая перезагрузка — правка скриптов без остановки Play.
- Cython в скриптах — вынос тяжёлой математики в компилируемые модули.
- ScriptComponent — компонент со стороны движка: пути, флаги, резолвинг класса, Check.
- Примеры скриптов — готовые поведения для копирования.
