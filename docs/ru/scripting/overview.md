# Обзор скриптинга

Поведения сущностей в ZarinEngine — обычные `.py`-файлы с классом поведения. Без базового класса, без регистрации, без шага сборки — сам файл и есть ассет.

Сквозной процесс:

1. `Project → Create → Python Script` создаёт файл внутри папки проекта. Держите скрипты рядом с использующим их контентом; соседние импорты (включая Cython-модули) резолвятся из папки скрипта автоматически.
2. Выберите сущность, `Inspector → Add Component → Scripts`, укажите файл в поле `Script`. Аннотированные атрибуты класса мгновенно становятся виджетами инспектора.
3. Настройте значения в инспекторе — они хранятся в сцене (`.zpes`), а не в `.py`-файле, так что один скрипт ведёт много настроенных инстансов.
4. Нажмите `Play`. Движок загружает класс, инстанцирует без аргументов, выставляет `self._entity`, вызывает `on_awake`, затем `on_start`.

Как устроено внутри:

- Движок находит первый класс в файле, объявляющий хотя бы один колбэк жизненного цикла, колбэк столкновений, метод гизмо или `_inspector_buttons`. Наследование не требуется; конструктор — без аргументов.
- Короткие имена — полноценные алиасы: `update` = `on_update`, `start` = `on_start` и так далее для awake, fixed_update, destroy, enable, disable. При обоих вариантах побеждает `on_*`.
- На одной сущности живут несколько `ScriptComponent` (`_allow_multiple = True`): движение, здоровье и визуал отдельными скриптами на одном объекте.
- Исключение в любом колбэке не роняет игру: пишется в консоль с именем скрипта и метода плюс трейсбек, кадр продолжается со следующего компонента.
- `script_path` хранится относительно корня проекта — сцены и скрипты чисто переезжают между машинами.

Контекст выполнения:

- `on_update(dt)` идёт в порядке сцены каждый кадр с `dt`, уже умноженным на time scale; `on_fixed_update(dt)` — на часах физики со стабильным шагом (`0.02` по умолчанию).
- Колбэки столкновений приходят из диспатча физики, а не ECS-цикла, с id другой сущности и опционально силой удара.
- Методы гизмо (`gizmo_lines`, `gizmo_meshes`) выполняются в редакторе даже вне Play для кастомных ручек и отладочной отрисовки.

Производительность: скрипты — Python и работают покадрово: держите `on_update` худым, кэшируйте лукапы компонентов в `on_start` вместо поиска по имени каждый кадр, числодробилку выносите в Cython-модули (см. Cython в скриптах).

Подстраницы:

- Колбэки жизненного цикла — каждый метод, сигнатуры и порядок вызовов.
- Поля инспектора и Range — аннотации в виджеты, Entity-пикеры, кнопки.
- API ввода и математики — подставляемые имена, клавиши, оси, векторы, кривые.
- Горячая перезагрузка — правка скриптов во время Play.
- Cython в скриптах — компилируемые хелперы без ручных сборок.
- ScriptComponent — пути, флаги, резолвинг класса, Check.
- Примеры скриптов — готовые поведения.
