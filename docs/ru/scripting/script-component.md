# ScriptComponent

`ScriptComponent` — движковая сторона пользовательских скриптов: загружает `.py`-файл, строит поля инспектора по классу, перенаправляет вызовы жизненного цикла, хранит значения полей в сцене и проверяет по требованию.

Факты о компоненте:

- `script_path` хранится относительно корня проекта — сцены переносимы. Относительный путь, не резолвящийся напрямую, повторно ищется от корня проекта; абсолютные резолвятся как есть.
- `hot_reload` по умолчанию `True`.
- Несколько инстансов живут на одной сущности (`_allow_multiple = True`).
- Шапка инспектора показывает отображаемое имя файла (базовое имя без расширения) с reveal-действием и кнопкой редактора; вторая шапка перечисляет найденные переменные скрипта.

Резолвинг класса по шагам:

1. Short-circuit по времени изменения: тот же `mtime` — кэшированный класс без работы.
2. Подготовка импортов: папка скрипта встаёт в поиск модулей, находятся соседние `.py` и собранные Cython-модули.
3. Сбор ошибок: парсинг синтаксиса, проверки `core.*`-импортов, пробное выполнение. При ошибках одно сводное `Script '...' has N error(s):` на версию файла, старый инстанс сбрасывается, полей нет до исправления.
4. Выполнение модуля с подставленным API (`Input`, `KeyCode`, `Vec2/3/4`, `Curve`, `Range`, `Logger`).
5. Выбор класса: первый класс в алфавитном порядке атрибутов (порядок `dir()`, а не порядок определения), хотя бы с одним колбэком жизненного цикла, колбэком столкновений, методом гизмо или `_inspector_buttons`. Инстанцируется без аргументов; `self._entity` выставляется перед каждым вызовом.
6. Кэширование методов: привязанные методы на каноническое имя с быстрыми флагами `on_update` / `on_fixed_update`; арности коллизий меряются один раз инспекцией сигнатуры; хинты полей кэшируются до изменения файла.

Сериализация: `script_path` и словарь `script_fields` сохраняются в `.zpes` — настроенные инстансы переживают перезагрузки, префабы и version control. `hot_reload` (по умолчанию `True`) — только рантайм-флаг и не сериализуется.

Действие `Check` запускает шаг 3 по требованию со строками `файл:строка: сообщение` — включая хинт `core.maths.math3d` против `core.math3d` и циклические импорты — сломанные скрипты диагностируются без Play.

Несколько инстансов на сущности держат независимые состояние модуля, инстанс и набор полей; перезагружаются независимо. Межскриптовое общение — через сущность (соседний скрипт — через его компонент, или общее состояние на сущности).
