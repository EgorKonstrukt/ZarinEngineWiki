# Cython в скриптах

Тяжёлые вычисления выносятся в Cython-модуль рядом с обычным скриптом — без ручных сборок и без мусора в папках скриптов.

Установка:

1. `Project → Create → Cython Script` — создаётся `fast_sum.pyx` с рабочим шаблоном.
2. В обычном скрипте той же папки пишется `import fast_sum`.
3. Перед импортом движок кладёт папку скрипта в поиск модулей, затем при первом импорте сам собирает расширение в `cache/cython`. На Windows встроенный MinGW находится самим движком.

```python
import move_fast


class Mover:
    speed: float = 5.0

    def on_update(self, dt):
        step = move_fast.clamp_step(self.speed * dt, 0.0, 1.0)
        t = self._entity.transform
        if t:
            t.translate(Vec3(0.0, 0.0, step))
```

```cython
cpdef double clamp_step(double value, double lo, double hi):
    if value < lo:
        return lo
    if value > hi:
        return hi
    return value
```

Правила и механика:

- Имя модуля — верхний уровень: `import foo`, где `foo.pyx` лежит рядом со скриптом. Имена уникальны в пределах проекта. Соседний `foo.pxd` тоже отслеживается для пересборок.
- Пересборки автоматические, когда `.pyx` (или `.pxd`) новее кэшированной сборки. Артефакты в `cache/cython`; папка скриптов чистая. Правка `.pyx` во время Play триггерит hot-reload как обычно.
- Кнопка `Check` проверяет `.pyx` без C-компилятора (только Cython-парсинг и типизация). Полная нативная сборка — лениво при первом импорте.
- Без компилятора в консоли понятная ошибка, а скрипт работает на предыдущей рабочей сборке — итерация никогда жёстко не блокируется тулчейном.
- Держите границу Python/Cython типизированной (`cpdef`, типированные локалы) и батчуйте вызовы: один вызов на массив бьёт поэлементные через границу.

Когда брать: покадровая математика по многим элементам (толпы, логика частиц, процедурные деформации), горячие циклы по профайлеру в скрипте, численные ядра. Игровой флоу, ввод и оркестрация остаются в обычном Python.

Диагностика: несвежие результаты — троньте `.pyx` (пересборкой правит `mtime`); ошибки импорта — коллизия имени модуля в проекте, переименуйте уникально; медленный первый Play — одноразовая компиляция, дальше переиспользуется `cache/cython`.
