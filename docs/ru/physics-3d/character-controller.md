# Контроллер персонажа

Кинематическое тело first/third-person на move-функции солвера — скольжение по склонам, подъём по ступеням и толкаемый реквизит без хаоса rigidbody.

Скорости по умолчанию: ходьба 260, бег 440 (Shift), крадучись 130, ускорение 10, ускорение в воздухе 10, трение 4, скорость остановки 80.

Прыжок и гравитация: сила 300, буфер 0.1 с, coyote 0.1 с. Прыжок работает, пока живы оба таймера (`can_jump = buffer > 0 and coyote > 0`, затем `velocity.y = jump_power`) — прощающий платформинг без лишнего кода.

Форма: радиус капсулы 0.5, высота 2.0 (итог минимум `radius * 2 + 0.1`), высота крадучись 1.2, высота шага 0.3, макс. склон 45°, сила толкания 30 по динамическому реквизиту.

Каждый fixed-шаг: проверка земли, ускорение с трением на земле, гравитация в воздухе, вызов `move_character` солвера с желаемой скоростью, запись позиции назад в трансформ, yaw-поворот. Повороты beyond yaw (pitch/roll) — на камере скриптом, никогда на теле.

Требование: солвер в процессе — контроллер читает состояние мира напрямую. В фоновых режимах движок откатывается на однопоточную физику с предупреждением («Use single-threaded physics mode»). Планируйте режим до шиппинга персонажного геймплея.

Обвязка ввода: читайте `Input.GetAxis`/клавиши в `on_update` в wish-направление, потребляйте в `on_fixed_update` для движения, прыжок по `GetKeyDown` с буфером самого контроллера. Синхронизируйте yaw камеры и тела одной чувствительностью.

Диагностика: падает вечно — нет коллайдера земли или маска исключила слой игрока; липнет на лестнице — высота шага ниже подступенка, поднимите до 0.35+; скользит на склонах — max slope выше угла или низко трение; дрожь на платформах — платформа kinematic с matching скоростью, парентуйте вместо толкания.

Связанное: Capsule-коллайдер (matching форма), Rigidbody (динамическая альтернатива), солвер и потоки (требование режима), API ввода.
