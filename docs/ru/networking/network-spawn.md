# NetworkSpawn

Пулы префабов и точки спавна: что может спавниться, где и по чьему триггеру.

| Группа / поле инспектора | Смысл |
|---|---|
| Network Spawn: Spawnable Prefabs | Белый список prefab id, доступных спавнеру |
| Spawn On Start | Заселить на старте сцены |
| Spawn Radius | Случайный диск вокруг спавнера |
| Randomize Rotation | Yaw-разнообразие на спавн |

API: `spawn(prefab_id)` на спавнере, `spawn_by_path(path)` для динамики, `spawn_player(peer)` для привязки подключения к аватару; `on_start` делает начальное заселение.

Белые списки — безопасность: ремоуты просят только перечисленные префабы, взломанный клиент не заспавнит админ-объекты. Spawn Radius декоррелирует кучные спавны (паки мобов, bursts лута); рандом поворота ломает визуальные повторы.

Паттерны: спавнер игроков (по одному на базу команд, spawn_player на вход), волновой спавнер (таймер-скрипт со spawn в интервал), спавнер лута (spawn на смерть врага), пад техники (spawn на интеракт, despawn на брошенность).

Авторитетный поток: запрос → хост валидирует префаб + кулдаун + кап → `spawn_prefab` → NetworkIdentity назначает Net ID → ремоуты инстанцируют по prefab id. Никогда не доверяйте клиентским spawn-вызовам напрямую.

Диагностика: ничего не спавнится — префаба нет в белом списке; не тот префаб на ремоутах — mismatch prefab id по сборкам; штормы спавна — нет кулдауна и капа, добавьте оба.

Связанное: NetworkManager (spawn_prefab/despawn), NetworkIdentity (id + prefab id), префабы (авторство), NetworkPlayer (привязка игроков).
