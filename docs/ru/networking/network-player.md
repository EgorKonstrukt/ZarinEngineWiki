# NetworkPlayer

Данные аватара на пира: имя, id, команда, флаг готовности и счёт — строка лобби как компонент.

| Группа / поле инспектора | Смысл |
|---|---|
| Network Player: Player Name | Отображаемое имя |
| Player ID | Зеркало id пира сессии |
| Team | Индекс или имя команды |
| Is Ready | Флаг готовности лобби |
| Score | Реплицируемый счётчик |

API: `set_ready(bool)`, `add_score(n)`, `set_team(t)`, `set_name(s)`, `apply_vars(data)` — путь снапшота, `on_awake` — регистрация.

Поток лобби: вход → спавн аватара с NetworkPlayer → клиент ставит имя/команду → `set_ready(True)` → хост считает готовности → матч стартует. Счёт идёт через `add_score`, и киллы/захваты/ассисты копятся на сервере без доверия клиенту.

`Is Local Player` на соседнем NetworkIdentity гейтит ввод; NetworkPlayer несёт социальные данные. Держите их на одном корне префаба — разнесённые корни рассинхронят имя и тело.

Диагностика: все имена дефолтные — set_name не вызван или применён до конца спавна; готовность игнорится — хост считает другой компонент, привяжите к этому; счёт сбрасывается — снапшот перезаписывает локальные сложения, складывайте только API на авторитете.

Связанное: NetworkIdentity (гейт Is Local Player), NetworkManager (поток входа/спавна), NetworkVariables (близнец репликации счёта).
