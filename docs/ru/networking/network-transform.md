# NetworkTransform

Экономный синк трансформа: какие оси едут, как часто, как ремоуты сглаживают, когда снапать.

| Группа / поле инспектора | Смысл |
|---|---|
| Sync: Sync Position / Rotation / Scale | Поканальные тоглы — статика не синкает ничего |
| Network Transform: Authority | TransformAuthority — кому можно писать |
| Send Rate | Обновлений в секунду на сущность |
| Pos / Rot Threshold | Минимальное изменение ради отправки (cutoff dead reckoning) |
| Interpolate | Сглаживание удалённого движения между снапшотами |
| Interp Delay | Буферная задержка против джиттера (выше = глаже + позже) |
| Teleport Threshold | Дистанция снапа: дальше — снап вместо скольжения |

API: `apply_snapshot(data)` — удалённый путь записи; `teleport(position)` — снап локально и удалённо; само движение читается в `on_update` из трансформа.

Настройка на архетип: игроки — позиция+поворот 20–30 Гц, мелкие пороги, interpolate вкл с задержкой ~100 мс; ящики — только позиция 5–10 Гц, грубые пороги; статичные двери — ничего до движения, затем teleport; гонщики за камерой — выше rate, ниже delay.

Пороги бьют сырые rate: поток 10 Гц с tight порогами часто везёт меньше данных, чем 30 Гц с нулевыми на idle-сценах. Teleport threshold спасает от скольжения через карту на респавне — ставьте около размера комнат уровня.

Диагностика: rubber-banding — мал delay под джиттер, поднимайте; moonwalking (лаг поворота) — груб порог rotation; снапы на лестнице — teleport threshold ниже шагов, поднимайте; мёртвые ремоуты — mismatch authority, записи rejected.

Связанное: NetworkIdentity (id + authority), NetworkRigidbody (физический близнец), NetworkManager (потолок tick rate).
